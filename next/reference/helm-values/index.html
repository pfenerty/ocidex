Helm values

The charts are published to oci://ghcr.io/pfenerty/charts. This page lists every value with its default and the comment that documents it in the chart’s values.yaml. A value whose default is a map or list shows it inline.

scannerWorker.resources.limits.memory 4Gi syft holds the file catalogue for the whole unpacked rootfs in memory, so the ceiling here is what decides the largest image that can be scanned – and exceeding it is an OOMKill, not a scan error: the container dies without writing last_error, the stuck sweep requeues the row, and the next attempt kills the worker again along with whatever else shared the pod. quay.io/cilium/cilium-envoy (one 1.05GB layer) looped that way for 13 days at 1536Mi. 4Gi covers it; images past SCANNER_MAX_IMAGE_BYTES are rejected from the manifest instead, so this limit and that ceiling must be raised together.

nats.podSecurityContext NATS has its own security context rather than reusing the chart-wide keys below: docker.io/nats:2-alpine declares no non-root user in /etc/passwd, so runAsNonRoot is only satisfiable with an explicit numeric runAsUser, which the project’s own images do not need. fsGroup is set for storage classes that honour it. Classes that do not (local-path is a hostPath provisioner; the kubelet applies fsGroup only to volume types supporting ownership management) still work on a fresh volume, because local-path creates the volume root 0777 and nats-server creates its own jetstream/ dir inside it as this uid. UPGRADE CAVEAT: an install predating ocidex-s3tu ran NATS as root, so its store dir is 0700 root:root and uid 1000 cannot open it — NATS dies with “[FTL] Can’t start JetStream: storage directory is not writable”. Recreate the PVC; see templates/NOTES.txt. The store is a doorbell cache, not the queue of record (ADR-024) — Postgres holds the jobs.

podSecurityContext Defaults satisfy the PodSecurity “restricted” profile so the chart installs into a namespace labelled pod-security.kubernetes.io/enforce=restricted (ocidex-1d9). securityContext readOnlyRootFilesystem is defence in depth, not a “restricted” requirement. Two workloads write to their own filesystem and mount emptyDirs over exactly the paths they need rather than dropping this setting: nginx (/run and /var/lib/nginx/tmp, deployment-web.yaml) and the scanner worker, whose syft dependency unpacks image layers into /tmp (deployment-scanner-worker.yaml). The vuln-worker writes only its grype database volume (deployment-vuln-worker.yaml). Adding a workload that shells out, unpacks archives, or caches to disk means auditing it against this setting — ocidex-gsip was six days of total scan outage from missing that step.

watchNamespace “” watchNamespace restricts the operator to reconciling CRs in the namespaces listed here. Required — prevents multiple operator instances from stepping on each other. Accepts a comma-separated list (“ocidex-dev,ocidex”). Changing this value is an operational contract, not a tuning knob: OCIRegistry resources carry an ocidex.io/registry-protection finalizer that only a watching operator removes, so any CR left in a namespace that drops off this list keeps its finalizer forever and leaves the namespace stuck Terminating (ocidex-1eo).
