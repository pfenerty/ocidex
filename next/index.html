The problem

Section titled “The problem”

You can generate an SBOM for every image you build. Most teams do, and then the SBOMs sit in a bucket or an attestation that nobody reads. The questions people actually ask stay hard:

  • A CVE was published this morning. Which of our images have it, and which of those are running?
  • This release is twice the size of the last one. What changed?
  • Legal wants to know. Where do we ship GPL code?

Each SBOM has the answer for one image at one moment. OCIDex puts them together so you can ask across all of them, and over time.

What it does

Section titled “What it does”

Collects SBOMs

Scans your container registries itself, or accepts CycloneDX SBOMs from CI, the CLI or the API. Every version is kept, per architecture and base distribution.

Diffs any two versions

A changelog for every artifact, and a diff between any two SBOMs, drawn as a dependency tree so you see what each change came in through.

Keeps vulnerabilities current

Matched against the grype database and re-matched daily. A new CVE shows up on an image you scanned months ago, with no rescan.

Knows what is running

A small agent reports what each Kubernetes cluster runs. OCIDex shows which of it is assessed, and can scan the rest for you.

Searches everything

Find a package by name across every SBOM, see each version in use and where, and browse every license by category.

Fits your access model

Namespaces with public or private visibility, five roles, sign-in with GitHub or any OIDC provider, and API keys that are never stronger than their owner.

A look around

Section titled “A look around”

Every artifact keeps its whole history: one SBOM per version and architecture, with its vulnerabilities and signing status.

The changelog shows what each new version added, removed and upgraded.

A cluster page shows what’s running, how much of it is assessed, and the worst of what’s exposed.

A package page shows every version of it in use, and which artifacts carry each.

How it compares

Section titled “How it compares”

OCIDex sits next to tools you may already run. It doesn’t replace most of them.

Tool What it is How OCIDex differs
syft, grype, Trivy Generate an SBOM, or scan one image, now OCIDex uses syft and grype inside. It keeps every result, compares them over time, and re-matches old SBOMs against new advisories.
Dependency-Track An SBOM and vulnerability platform built around projects and policy OCIDex is built around container images: registry scanning, multi-arch and distro-aware changelogs, image provenance, and what’s running in clusters.
Registry scanners (Harbor, GHCR, ECR) Scan the images in one registry OCIDex works across registries and uploads, keeps the full SBOM, and diffs versions.
GUAC A graph of supply-chain metadata to query OCIDex is a ready-to-use application with a UI, rather than a graph to build tooling on.
